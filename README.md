## ما هذا المشروع

بحيرة سمارت ليس موقعًا حكوميًا ولا مجموعة صفحات. هو **طبقة وساطة ذكية** بين المواطن والمحافظة،
تحلّ مشكلة حقيقية في اتجاهين:

> المواطن لا يعرف **الجهة** ولا **الإجراء** ولا **المستندات** ولا **حالة طلبه**.
> والمحافظة لا ترى **الصورة الكلية** لما يشتكي منه الناس.

```
المواطن ──▶ نية ──▶ توجيه ذكي ──▶ خدمة / بلاغ / كورس / خبر
                                          │
                                   بيانات منظمة
                                          │
                                   تحليل (AI)
                                          ▼
المحافظة ◀── قرار أفضل ◀── رؤية تنفيذية ◀── مؤشرات وتجميعات
```

## التشغيل

```bash
npm install
npm run dev          # http://localhost:3000
```

```bash
npm run build && npm run start   # نسخة الإنتاج
npm run typecheck                # فحص الأنواع
```

تُنشَأ قاعدة البيانات وتُغذّى بالبيانات التجريبية **تلقائيًا** عند أول تشغيل، في
`.data/beheira.db`. لإعادة بنائها من الصفر: احذف المجلد `.data` وأعد التشغيل.

> **متطلب وحيد:** Node.js 22 أو أحدث (نستخدم وحدة `node:sqlite` المدمجة).
> لا توجد اعتماديات أصلية (native) ولا خدمات خارجية ولا مفاتيح API.

## الوحدات الست

| الوحدة | المسار | الفكرة |
|---|---|---|
| **أخبار البحيرة** | `/news` | القناة الرسمية: قرارات، إعلانات، فعاليات، فرص، تنبيهات — وكل خبر يقود إلى خدمة |

| **ذكاء المحافظة** | `/admin` | مؤشرات، بؤر، رؤى تنفيذية بالدليل، وإدارة بصلاحيات حسب الدور |

## ما يميّزه تقنيًا

### ١. محرك ذكاء عربي محلي — يعمل دون إنترنت وقابل للتفسير

بدل استدعاء نموذج لغوي خارجي، بنينا محرك استدلال عربيًا داخل التطبيق:

- **تطبيع عربي**: توحيد الهمزات والألف والتاء المربوطة والياء، حذف التشكيل والتطويل، تجريد خفيف للسوابق واللواحق.
- **تصنيف البلاغات**: مطابقة موزونة على معاجم مكتوبة **بالعامية المصرية** كما يكتبها المواطن فعلًا.
- **تقدير الأولوية**: إشارات خطورة + قرب المواقع الحساسة + تكرار جغرافي.
- **كشف التكرار**: تشابه جاكارد على الجذوع + مسافة هافرساين + تقارب زمني.
- **التجميع الجغرافي**: نمو من البذرة داخل نافذة ٧٢ ساعة ونطاق ١٫٥ كم.
- **توليد الرؤى**: كشف القفزات بتنعيم جمعي، البؤر، تجاوز مدة الاستجابة.

**لماذا محليًا؟** ثلاثة شروط حكومية حقيقية تفرضه: العمل على شبكة ضعيفة، وعدم إرسال بيانات
المواطنين لطرف ثالث، و**قابلية التفسير** — الموظف يرى *لماذا* صُنِّف البلاغ هكذا.
النموذج اللغوي يبقى تحسينًا اختياريًا خلف واجهة، لا شرطًا للتشغيل.

### ٢. الذكاء الاصطناعي يساعد ولا يقرر

قيد **تصميمي في الكود**، لا صياغة لغوية:

- المواطن يرى التصنيف المقترح **والكلمات التي بُني عليها**، ويعدّله قبل الإرسال.
- الموظف يرى الرؤية **ومعها دليلها** والإجراء المقترح — ولا شيء يُنفَّذ تلقائيًا.
- كل تغيير حالة يُسجَّل باسم من نفّذه ووقته (سجل تدقيق).

### ٣. عمل حقيقي دون اتصال

```
Service Worker ─ الأصول (cache-first) · الصفحات (network-first)
IndexedDB      ─ ما فتحه المواطن فعلًا + طابور الإرسال
كاشف الاتصال   ─ مزامنة تلقائية عند عودة الشبكة
```

**نقول بصراحة ما لا يعمل:** إرسال بلاغ وحجز مقعد يحتاجان تأكيد الخادم — يُحفظان في طابور
بمفتاح تفرّد (idempotency key) يمنع الازدواج عند إعادة المحاولة.

### ٤. لا بيانات حكومية مكتوبة في الواجهة

الرسوم والمواعيد والمستندات تتغير بقرار إداري لا بإصدار برمجي — لذلك تُحرَّر كلها من
لوحة المحافظة، ويظهر **تاريخ آخر تحديث** للمواطن على كل خدمة.

## البناء التقني

| الطبقة | الاختيار | السبب |
|---|---|---|
| الواجهة والخادم | Next.js 16 · React 19 · TypeScript | تطبيق واحد للموبايل والديسكتوب، عرض من الخادم = سرعة على شبكات ضعيفة |
| قاعدة البيانات | SQLite عبر `node:sqlite` | قاعدة حقيقية بمعاملات وفهارس، **بصفر اعتماديات أصلية** وبلا تكلفة تشغيل |
| التصميم | نظام تصميم مبني خصيصًا · Tailwind v4 | لا مظهر قوالب جاهزة |
| الرسوم والخرائط | SVG مكتوب يدويًا | تحكم كامل في RTL، بلا خدمات خارجية، ولا تسريب مواقع البلاغات |

```
src/
├── app/            المسارات — (citizen) للمواطن · admin للمحافظة · api للمعالجات
├── components/     brand · ui · layout · modules · charts
├── lib/
│   ├── ai/         arabic · classifier · similarity · insights · recommender · assistant
│   ├── db/         driver · schema · seed
│   ├── repositories/  الطبقة الوحيدة التي تعرف شكل الجداول
│   ├── offline/    idb · outbox
│   └── auth/       session · rbac
└── data/           بيانات العرض التوضيحي (geo · services · news · courses · complaints)
```

**حدّ معماري مقصود:** `src/lib/complaint-status.ts` وحدة خالصة بلا اعتماد على قاعدة البيانات،
لأن ثوابتها يحتاجها العميل والخادم معًا — ولو بقيت داخل المستودعات لسحبت `node:sqlite`
إلى حزمة المتصفح.

## مسار العرض التقديمي (٤ دقائق)

| # | الخطوة | الرسالة |
|---|---|---|
| ١ | الصفحة الرئيسية | لقطة واحدة تُعرّف المشروع |
| ٢ | «عايز أجدد بطاقة الرقم القومي» في المساعد ← ملف الخدمة | **اللحظة الفاصلة**: نية بالعامية ← إجراء |
| ٣ | خبر رسمي ← الخدمة المرتبطة به | المعلومة تقود إلى فعل |
| ٤ | كورس ← حجز مقعد | منظومة تعلم لا قائمة |
| ٥ | بلاغ بصورة ← النظام يقترح ← المواطن يراجع | ذكاء مسؤول، إنسان في الحلقة |
| ٦ | **اقلب إلى `/admin`** — البلاغ دخل، وانضم إلى بؤرة، وولّد رؤية | الحلقة أُغلقت |
| ٧ | اقطع الشبكة وتصفّح المحفوظ | يعمل في الواقع لا في المثالي |

> **جملة الختام:** «البلاغ الذي أرسلناه قبل تسعين ثانية أصبح الآن مؤشرًا على شاشة المحافظة.»

**للأدوار في اللوحة:** بدّل الدور من الشريط الجانبي في `/admin` لرؤية اختلاف الصلاحيات
(مدير عام · مدير أخبار · مدير خدمات · مدير كورسات · مدير بلاغات · محلل).

## حدود هذا النموذج — بصراحة

- **كل البيانات عرض توضيحي.** صيغت على نمط البيانات الرسمية، ولا تمثّل مصدرًا حكوميًا.
  تحقّق دائمًا من الجهة المختصة.
- **لا يوجد ربط بأي نظام حكومي حقيقي.** المعمارية مصممة ليُضاف لاحقًا دون إعادة بناء الواجهة.
- **المصادقة نموذج أولي** بلا كلمات مرور. في التشغيل تُستبدل بمزود هوية حكومي، ويبقى كل ما
  فوقها كما هو لأن الواجهة هي `getCurrentUser()` فقط.
- **الخريطة تمثيل تخطيطي** مبني على إحداثيات تقريبية لمراكز البحيرة، وليست مسحًا جغرافيًا رسميًا.
- **المرفقات في الأخبار توضيحية** وغير قابلة للتحميل.

### الشعار

العلامة المستخدمة هي **علامة المنتج** التي صمّمناها — قرص الشمس بين مرتفعين (علامة الأفق
«آخِت» في الكتابة المصرية القديمة) فوق خطوط ماء تشير إلى الدلتا والبحيرة. **وهي ليست الشعار
الرسمي للمحافظة**، ولم نُقدّم أي رسم على أنه كذلك.

لاستخدام الشعار الرسمي: ضع الملف في `public/brand/beheira-logo.svg` واستعمل مكوّن
`<OfficialCrest />` — يُعرض كما هو دون تلوين أو تشويه، احترامًا لدليل الهوية الرسمي.
