## A. معمارية المنتج · Product Architecture

بحيرة سمارت ليست مجموعة صفحات حكومية، بل **طبقة وساطة ذكية** بين المواطن والمحافظة.
المشكلة الحقيقية التي نحلها ليست "عدم وجود موقع"، بل:

> المواطن لا يعرف **الجهة**، ولا **الإجراء**، ولا **المستندات**، ولا **المكان**، ولا **حالة طلبه**.
> والمحافظة لا ترى **الصورة الكلية** لما يشتكي منه المواطنون.

فنبني اتجاهين متقابلين على نفس البنية:

```
المواطن ──▶ نية (Intent) ──▶ توجيه ذكي ──▶ خدمة / بلاغ / كورس / خبر
                                                  │
                                                  ▼
                                          بيانات منظمة (Structured)
                                                  │
                                       تحليل ذكي (AI Layer)
                                                  │
                                                  ▼
المحافظة ◀── قرار أفضل ◀── رؤية تنفيذية ◀── مؤشرات وتجميعات
```

### الأعمدة الستة

| العمود | الوظيفة | لمن |
|---|---|---|
| **أخبار البحيرة** | القناة الرسمية للمعلومة | مواطن |
| **الخدمات الحكومية** | اكتشاف بالنية لا بالاسم الرسمي | مواطن |
| **البلاغات الذكية** | إبلاغ + تتبع + تصنيف مساعَد | مواطن ↔ حكومة |
| **كورسات البحيرة** | منظومة تعلم حكومية | مواطن |
| **المساعد الذكي** | طبقة تفاعل عرضية فوق كل الوحدات | مواطن |
| **ذكاء المحافظة** | دعم القرار | حكومة |

### مبدأ حاكم: المساعد ليس وحدة، بل طبقة
المساعد لا يعيش في صفحة واحدة. هو **موجّه (Router)** يعمل من الصفحة الرئيسية، من شريط البحث، ومن أي شاشة، ويُخرج **إجراءات** لا فقرات نصية.

## C. ترتيب الأولويات · Feature Prioritization

**P0 — يُبنى بالكامل (قلب العرض التقديمي)**
التنقل · الأخبار · الخدمات بالنية · المساعد · البلاغات + تصنيف مساعَد · الكورسات + الحجز · لوحة الذكاء الحكومي · موبايل/ديسكتوب · RTL

**P1 — يُبنى بعمق كافٍ للإقناع**
التخزين دون اتصال · طابور المزامنة · كشف التكرار · التجميع الجغرافي · الرؤى التنفيذية · الأدوار · الإشعارات · التوصيات

**P2 — مُعمَّر له، غير مُنفَّذ (ويُقال ذلك صراحة)**
ربط حقيقي بأنظمة حكومية · الدفع الإلكتروني · مصادقة إنتاجية (بوابة مصر الرقمية) · نماذج لغوية كبيرة مستضافة · تطبيق أصلي

> **قاعدة صدق:** أي شيء غير مربوط بنظام حكومي حقيقي يُعرض كـ **بيانات عرض توضيحي** ويحمل وسم `بيانات تجريبية`. لا ندّعي تكاملًا لا نملكه.

## D. رحلات المستخدم · User Journeys

**١. من الإعلان إلى الفعل**
إشعار رسمي ← فتح الخبر ← "الخدمات المرتبطة" ← ملف الخدمة ← معرفة المستندات والمكان.

**٢. من النية إلى الخدمة** *(الرحلة الأقوى)*
«عايز أجدد بطاقة الرقم القومي» ← المساعد يفهم النية ← بطاقة إجراء ← ملف الخدمة: مستندات + نماذج + رسوم + مواعيد + أقرب مكتب + ملاحظات.

**٣. من الرغبة إلى المقعد**
كورسات ← تصفية ← صفحة كورس ← المنهج والمدرب والمقاعد ← حجز ← تأكيد.

**٤. من المشكلة إلى البلاغ**
تصوير ← وصف ← الموقع ← **الذكاء يقترح التصنيف والأولوية** ← المواطن **يراجع ويعدّل** ← تحذير من بلاغ مشابه ← رقم بلاغ ← تتبع.

**٥. من البلاغ إلى القرار** *(الحلقة تُغلق)*
لوحة المحافظة ← البلاغ يدخل ← الذكاء يجمّعه مع ٨ بلاغات في نفس النطاق ← رؤية: «تركّز غير طبيعي لبلاغات الإنارة في كفر الدوار خلال ٧٢ ساعة» ← إجراء مقترح.

## F. المعمارية التقنية · Technical Architecture

```
┌───────────────────────────────────────────────┐
│ Presentation — Next.js App Router (RSC)       │
│  Server Components للقراءة · Client للتفاعل    │
├───────────────────────────────────────────────┤
│ Application — Route Handlers /api/*           │
│  تحقق من المدخلات · RBAC · تشكيل الاستجابة     │
├───────────────────────────────────────────────┤
│ Domain — Repositories (src/lib/repositories)  │
│  المنطق الوحيد الذي يعرف شكل البيانات           │
├───────────────────────────────────────────────┤
│ Data — DataDriver                             │
│  SQLite (node:sqlite, بلا اعتماديات أصلية)     │
│  ↔ قابل للاستبدال بـ PostgreSQL دون لمس ما فوقه │
├───────────────────────────────────────────────┤
│ AI Services · Auth · Notifications · Sync     │
└───────────────────────────────────────────────┘
```

**لماذا هذه الاختيارات**
- **Next.js 16 + React 19** — تطبيق واحد يخدم الموبايل والديسكتوب، عرض من الخادم = سرعة على شبكات ضعيفة، ومسار واضح للنشر.
- **`node:sqlite` المدمج في Node 22** — قاعدة بيانات حقيقية بمعاملات (transactions) و**صفر اعتماديات أصلية**؛ لا تعطل البناء، ولا تكلفة تشغيل. ملف واحد يمكن أخذ نسخة منه.
- **طبقة `DataDriver`** — على خادم للقراءة فقط (serverless) يسقط تلقائيًا إلى قاعدة في الذاكرة مُغذّاة بالبذور. الترقية إلى PostgreSQL = تنفيذ واجهة واحدة.
- **بلا مكتبة واجهة جاهزة** — نظام تصميم مبني خصيصًا؛ لا مظهر قوالب.
- **رسوم بيانية SVG مكتوبة يدويًا** — تحكم كامل في RTL والألوان، وبلا وزن إضافي.

## G. معمارية الذكاء الاصطناعي · AI Architecture

**المبدأ الحاكم: الذكاء الاصطناعي يساعد ولا يقرر.**
لا نُسند للنظام قرارًا حكوميًا. كل مخرج ذكي يمر على إنسان: المواطن يراجع التصنيف، والموظف يراجع الرؤية.

```
                 ┌──────────────────────────────┐
                 │        AIService (واجهة)      │
                 └───────────────┬──────────────┘
          ┌──────────────────────┴──────────────────────┐
          ▼                                             ▼
  LocalEngine (الافتراضي)                        LLMDriver (اختياري)
  استدلالي · شفاف · يعمل دون إنترنت              يُفعَّل بمفتاح، لصياغة أفضل
```

**لماذا محرك محلي أولًا؟** لأن ثلاثة شروط حكومية حقيقية تفرضه: العمل دون إنترنت، وعدم إرسال بيانات المواطنين لطرف ثالث، و**قابلية التفسير** — الموظف يجب أن يرى *لماذا* صُنِّف البلاغ هكذا. النموذج اللغوي يبقى تحسينًا اختياريًا خلف واجهة، لا شرطًا للتشغيل.

**المكوّنات**
1. **تطبيع عربي** — توحيد الهمزات والألف والتاء المربوطة والياء، حذف التشكيل والتطويل، تجاهل كلمات الوقف.
2. **تصنيف البلاغات** — تطابق موزون على معاجم فئات + تعزيز بالسياق، يُخرج `{فئة, ثقة, إشارات[]}`. **الإشارات معروضة للمستخدم** — هذا ما يجعله قابلًا للتدقيق.
3. **تقدير الأولوية** — إشارات خطورة (تسريب غاز، كهرباء مكشوفة، مدرسة/مستشفى) + تكرار جغرافي + حساسية الفئة.
4. **كشف التشابه** — Jaccard على الرموز + مسافة هافرساين + تطابق الفئة ⇒ تحذير تكرار **قبل** الإرسال.
5. **التجميع الجغرافي** — شبكة جغرافية × فئة × نافذة زمنية ⇒ بؤر.
6. **توليد الرؤى** — كشف الارتفاعات المفاجئة، البؤر، تجاوز مدة الاستجابة، مقارنة بالمتوسط ⇒ جملة عربية تنفيذية + **الدليل** المستند إليه.
7. **التوصية التعليمية** — تشابه محتوى على الاهتمامات والمستوى والمسارات.
8. **موجّه النية** — تصنيف نية + استخراج كيانات ⇒ **بطاقات إجراء**، لا فقرات.

## H. معمارية العمل دون اتصال · Offline / Sync

```
Service Worker ─ shell + assets (cache-first)
      │         ─ صفحات ومحتوى (stale-while-revalidate)
      ▼
IndexedDB ─ content   (أخبار وخدمات وكورسات مقروءة سابقًا)
          ─ saved     (المحفوظات)
          ─ outbox    (طابور الإرسال)
      │
      ▼
كاشف الاتصال ──▶ مزامنة الطابور ──▶ الخادم ──▶ حل التعارض
```

**ما يعمل دون اتصال:** تصفح ما سبق فتحه، المحفوظات، ملفات الخدمات ومستنداتها، البلاغات السابقة، **وكتابة مسودة بلاغ**.
**ما لا يعمل — ونقولها في الواجهة:** إرسال بلاغ نهائي، حجز مقعد، وأي عملية تحتاج تأكيدًا من الخادم. تُوضع في الطابور وتُرسل عند عودة الشبكة.

**التعارض:** الخادم مرجع للحالة الرسمية (server-authoritative). المسودات محلية بآخر-كتابة-تفوز. المُرسَلات تحمل مفتاح تفرّد (idempotency key) يمنع الازدواج عند إعادة المحاولة.

## I. معمارية الإدارة · Admin Architecture

صلاحيات قائمة على الأدوار، معرَّفة كمصفوفة واحدة `(role × resource × action)` تُطبَّق في مكان واحد وتُفرض على الخادم — لا إخفاء أزرار فقط.

| الدور | الصلاحية |
|---|---|
| مدير عام | كل شيء |
| مدير الأخبار | الأخبار والإشعارات |
| مدير الخدمات | الخدمات والأماكن والمستندات والرسوم |
| مدير الكورسات | الكورسات والمدربون والحجوزات |
| مدير البلاغات | البلاغات والتصنيفات والحالات |
| محلل | قراءة التحليلات فقط |

كل تغيير حالة بلاغ يُسجَّل كحدث بفاعل ووقت — سجل تدقيق، لأن هذا شرط في أي نظام حكومي حقيقي.

## J. نظام التصميم · Design System

**الفكرة:** تراث مصري أُعيد تصميمه لحكومة رقمية مستقبلية — بإشارات خفيفة، لا زخرفة صريحة.

- **اللون:** كحلي نيلي عميق (`--nile`) أساس · ذهب رملي (`--gold`) للتمييز فقط · فيروزي (`--faience`) للعناصر الحية · أبيض دافئ للأسطح. الذهب لا يُستخدم كخلفية عريضة — يُستخدم كخيط وحدّ وإشارة، كما يُستخدم الذهب في الحرف المصري.
- **الإشارة التراثية:** شبكة هندسية مشتقة من نِسب المعابد، خط ذهبي رفيع أسفل العناوين الرسمية، وزخرفة حدودية دقيقة في الترويسة فقط. **لا أهرامات. لا هيروغليفية زخرفية عشوائية.**
- **هوية البحيرة:** تدرج مائي يشير إلى النيل ورشيد والبحيرة نفسها في أسطح البطاقات الكبرى.
- **الخط:** IBM Plex Sans Arabic للنصوص (وضوح عالٍ في الأحجام الصغيرة)، Cairo للعناوين. الأرقام العربية الشرقية للتواريخ العرضية، والأرقام اللاتينية للأرقام المرجعية والكميات — لأن هذا ما يقرأه الناس فعليًا على الأوراق الرسمية.
- **المسافات:** سلم 4px. حواف: 10/14/20px — لا مستطيلات ضخمة الاستدارة.
- **العمق:** ظلال دقيقة بلون الكحلي لا الأسود. الزجاجية في موضعين فقط: الترويسة الملتصقة وشريط الموبايل السفلي.
- **الحركة:** 150–260ms، `cubic-bezier(.2,.8,.2,1)`. الحركة تشرح العلاقة (من أين أتت الشاشة) أو الحالة (وصل/فشل). تحترم `prefers-reduced-motion`.
- **الحالات:** لكل شاشة أربع حالات مصممة — تحميل (هيكل عظمي)، فارغة، خطأ، نجاح.
- **RTL:** خصائص منطقية حصرًا (`ms-`, `me-`, `ps-`, `pe-`, `start-`, `end-`)؛ الأسهم الاتجاهية تُقلب؛ الأرقام والمصطلحات اللاتينية داخل نص عربي تُعزل باتجاه صريح.

**الشعار:** الملف يُوضع في `public/brand/beheira-logo.svg` فيُستخدم تلقائيًا في الترويسة وشاشة البدء و الأيقونات. لحين توفيره يُعرض شعار المنتج الخاص بنا (`Beheira Smart`) — ولا يُقدَّم أي رسم على أنه الشعار الرسمي للمحافظة.

## K. استراتيجية العرض التنافسي · Demo Strategy

**عرض واحد متصل مدته ٤ دقائق، لا جولة في القوائم.**

| # | ما يُعرض | الرسالة للحكّام |
|---|---|---|
| 0 | الصفحة الرئيسية | لقطة واحدة تُعرّف المشروع |
| 1 | إشعار رسمي ← خبر ← خدمة مرتبطة | المعلومة تقود إلى فعل |
| 2 | «عايز أجدد بطاقة الرقم القومي» ← المساعد ← ملف الخدمة | **هذه اللحظة التي نفوز بها** |
| 3 | كورس ← حجز مقعد | منظومة تعلم لا قائمة |
| 4 | بلاغ بصورة ← الذكاء يقترح ← المواطن يراجع | ذكاء مسؤول، إنسان في الحلقة |
| 5 | **قلب الشاشة إلى لوحة المحافظة** — البلاغ ظهر، تجمّع مع ٨، رؤية تنفيذية | الحلقة أُغلقت |
| 6 | قطع الشبكة وتصفّح المحفوظ | يعمل في الواقع لا في المثالي |

**جملة الختام:** «البلاغ الذي أرسلناه قبل تسعين ثانية أصبح الآن مؤشرًا على شاشة المحافظة.»

**ما نقوله بصراحة عند السؤال:** البيانات تجريبية واقعية، المصادقة نموذج أولي، ولا يوجد ربط بأنظمة حكومية حقيقية — والمعمارية جاهزة له. الصدق هنا يكسب ثقة الحكّام، ولا يخسر نقاطًا.
